## Task 1: Bounded authenticated batch read API

Own api/, go-server/, flutter/api/ generated Dart only. Add POST /api/v3/batch, operationId batchRead, tag Batch, generated server and Dart client. Request {requests: [{kind, id}]} maximum 100 entries, minimum 1, unique processing where possible. Kinds: pinImage, userImageSmall, userImage, groupImageSmall, groupImage, groupPinImage, user, pinLikes. id UUID. Response {results:[{kind,id,status,imageUrl?,user?,likes?}]}; user references existing userInfoDto, likes existing pinLikeDto. Empty/malformed/over-limit/unknown-kind input yields 400; missing auth 401. Per-resource failures use status in results (no credentials, no data for errors), preserving existing endpoint authorization, soft-delete and caller-specific likes semantics. Do not turn hidden pin/group resources into public media. Reuse existing handlers/services in-process so no HTTP loopback calls; bounded sequential service reads acceptable in this step (web batching, not SQL optimization). Propagate context/cancellation, don't convert transient server errors into successful empty resources. Keep old individual endpoints unchanged. Generate Go embedded contract/server controllers and complete Dart client with pinned tools. Keep authoring fragments synchronized. Add meaningful failing then passing tests for route auth, malformed input/bounds, mixed accessible/forbidden resources, caller-specific likes, user and all image kinds against disposable PostGIS (may omit RustFS URL check if separate unit validated but report limitation). Coordinate constructor/router carefully. DB queries only if actually needed, with generators/tests if so.
